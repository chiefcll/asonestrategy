# As One Strategy static site: design

- **Date:** 2026-09-25
- **Status:** approved in chat, awaiting spec review
- **Design source:** the "As One Strategy Website" design canvas
  (https://claude.ai/artifact/4TVHjgSCUHubLDrmgyWG2d), artboard `Main.dc.html`, a 1440 px desktop board.

## Goal

Replace the Hugo site in this repo with a hand-written static site that implements the design.
The site must stay centered and work at every screen size, and it is served at https://asonestrategy.com from
GitHub Pages. It uses the same tooling, form backend and deploy flow as `../solidtv.dev`.

## Decisions

| Topic | Decision |
| --- | --- |
| Stack | Hand-written HTML + Tailwind CSS v3 CLI (same major as solidtv.dev). No templating, no JS framework. |
| Package manager | pnpm |
| Hosting | GitHub Pages, "Deploy from a branch", `main` branch, `/docs` folder (same as solidtv.dev). |
| Domain | `asonestrategy.com` through `docs/CNAME`. GitHub redirects `www` to the apex. |
| Form backend | Web3Forms with a **new access key registered to hello@asonestrategy.com**, hCaptcha, honeypot, redirect to a thanks page. |
| Analytics | GA4 `G-6W5XT0VM94` on both pages, `generate_lead` on the thanks page, `cta_click` on `[data-cta]` links. |
| Mobile header | Below 768 px: logo + "Let's talk" button only. |
| Copy | Taken verbatim from the design. No rewrites. |
| Links | Relative URLs: `images/logo.jpg`, `#contact` inside `index.html`, `./#contact` from `thanks.html`. Absolute URLs only where they must be: canonical, Open Graph, form redirect, sitemap, JSON-LD. |
| Git | Keep history. Work on branch `static-site`, merge to `main` by PR. |
| Not carried over from solidtv.dev | husky, lint-staged, prettier, eslint scripts. None of them touch HTML, and solidtv.dev's eslint script has no eslint installed. |

Out of scope: copy edits, extra pages, a blog, a 404 page, a cookie banner (solidtv.dev has none), rewriting git history.

- **Fonts:** Montserrat 500/600/700/800 for display, labels, nav and buttons. Source Sans 3 400/500/600 for body
  text. Both load from Google Fonts with `display=swap`.
- **Radii:** 4 px for buttons and inputs, 8 px for cards, photos and the form card.
- **Eyebrow labels:** Montserrat 700, 13–14 px, letter-spacing 0.16–0.24 em, uppercase, `brand`. The hero and
  contact eyebrows start with a 48x3 px `accent` bar.
- **Contrast:** white on `accent` is 5.5:1 and `brand` on `paper` is 5.9:1, so both pass WCAG AA.

## Page structure

`index.html` follows the design in this order: header, hero (`#top`), About (`#about`), Services (`#services`),
Team (`#team`), Contact (`#contact`), footer. There is a visually hidden "Skip to content" link before the header.
Chris's `[PHOTO]` placeholder becomes `chris-lorenzo.jpg`.

## Layout and responsive rules

**Centering:** every section's background spans the full viewport width. Inside each section, content sits in a
centered column (`max-w-[1440px] mx-auto`). Side padding is 24 px below 768, 48 px from 768 to 1279, and 96 px
from 1280 up, so the content column maxes out at 1248 px, the design's width. Text stays left-aligned as in the
design.

**Breakpoints:** Tailwind defaults: `sm` 640, `md` 768, `lg` 1024, `xl` 1280. Desktop values (≥1280) match the
design exactly. Where a rule lists three sizes as "a / b / c", they apply at ≥1280 / ≥768 / below 768.

**Shared rules:**
- Vertical padding for the About, Services, Team and Contact sections: 128 / 96 / 64 px.
- Section headings: 44 / 36 / 30 px.
- Below 768, card and service titles drop from 26 to 22 px and team names from 28 to 24 px.
- Below 768, body text drops as follows: 20 → 18 px (About paragraphs), 19 → 17 px (service text), 18 → 17 px
  (cards, team bios).

**Per section:**

- **Header:** sticky at the top, white, 1 px `line` bottom border.
  - ≥768: 104 px tall, 64 px logo, the About / Services / Team links plus the "Let's talk" button.
  - <768: 72 px tall, 44 px logo, the "Let's talk" button only, 44 px tall with 20 px horizontal padding.
- **Hero:**
  - Headline: 72 / 56 / 40 px.
  - Lead paragraph: 22 / 20 / 18 px.
  - Vertical padding (top/bottom): 120/128 px, 96/104 px, 64/72 px.
  - Buttons: sit side by side and wrap. Below 640 each is full width.
  - Arcs: the two-arc SVG fills the column width with `preserveAspectRatio="none"` and a non-scaling 6 px stroke.
    It is 72 px tall ≥768 and 40 px tall below.
- **About:**
  - Heading and paragraphs: two columns ≥1024 (gap 64 at `lg`, 96 at `xl`), stacked below. The paragraph
    column's 40 px top offset applies ≥1024 only.
  - Hannah/Chris cards: two columns ≥768, stacked below. Card padding is 48 / 32 / 24 px.
- **Services:**
  - Intro row (title block + 460 px paragraph): side by side ≥1024, stacked below.
  - Service rows: three columns ≥1024. The number column is 96 px at `xl` and 64 px at `lg`. The title column is
    400 px at `xl` and 300 px at `lg`.
  - Below 1024 a row has two columns: a 48 px number, then the title with the text beneath it.
  - Row padding: 36 px top and bottom ≥1024, 28 px below.
  - Row dividers: the first row has a 2 px `ink` top border, every other row a 1 px `rule` one, and the last
    row also gets a 1 px `rule` bottom border.
- **Team:**
  - Members: side by side ≥1280 (gap 48), one per row below. With one per row, bio text is capped at 640 px wide
    so lines stay readable.
  - Photo and bio: side by side ≥640. Below 640 the photo sits above the bio.
  - Photo size: 200x240 px (as designed) at ≥1440, 160x192 px below, with `object-fit: cover`. The smaller photo
    keeps the two-up bios about as wide as the design's between 1280 and 1439. Hannah keeps the design's
    `object-position: center 25%`.
- **Contact:**
  - Layout: dark `ink` band. Text and form in a `5fr 6fr` grid ≥1024 (gap 64 at `lg`, 96 at `xl`), stacked below
    (gap 48).
  - Text sizes: heading 56 / 44 / 34 px. The sub-line is 24 px ≥768 and 20 px below.
  - Email and phone links are at least 44 px tall.
  - Form card padding: 48 / 32 / 20 px.
  - Name/Email and Organization/Phone pair up ≥640, one per row below.
  - The submit button is full width below 640.
- **Footer:** white, 1 px `line` top border. ≥768 it is one row: logo on the left, email, phone and © on the right.
  Below 768 everything stacks, centered.
- **Scrolling:** `scroll-padding-top` matches the header height (104 / 72 px) so anchor links land below the sticky
  header. `scroll-behavior: smooth` applies only under `prefers-reduced-motion: no-preference`.
- **Focus:** links, buttons and inputs show a visible 2 px `accent` focus outline (`:focus-visible`) with a 2 px
  offset. It clears 3:1 against both white and `ink`.

## Contact form

- **Backend settings:**
  - `action="https://api.web3forms.com/submit"`, `method="POST"`.
  - Hidden fields: `access_key` (the new key), `subject` = `New inquiry from asonestrategy.com`,
    `from_name` = `asonestrategy.com`, `redirect` = `https://asonestrategy.com/thanks.html`.
  - Honeypot: `<input type="checkbox" name="botcheck" class="hidden" style="display: none" tabindex="-1" autocomplete="off">`.
  - hCaptcha: `<div class="h-captcha" data-captcha="true"></div>` above the submit button, plus
    `<script src="https://web3forms.com/client/script.js" async defer></script>` in the head.
  - hCaptcha sizing: the widget is a fixed 303 px wide, and below 768 the card's inner width is the viewport width
    minus 88 px. So below 400 px the `.h-captcha` box is scaled with `transform-origin: left top`: `scale(0.89)`
    from 360 to 399 px and `scale(0.75)` below 360 px. It then fits inside the card at 320 px and up.
- **Fields,** labels and order as designed:
  - `name`: text, required, `autocomplete="name"`.
  - `email`: email, required. Web3Forms uses it as the reply-to address.
  - `organization`: text, `autocomplete="organization"`.
  - `phone`: tel, labeled "(optional)".
  - `interest`: select. Options: Not sure yet (default), Organizational Development, Leadership Development,
    Curriculum and Training Design, Systems Performance Review, Strategic Advisory.
  - `message`: textarea, 5 rows, required, labeled "What's in the way?".
- **Input font size:** stays 17 px, which keeps iOS from zooming on focus.
- **`thanks.html`:**
  - Uses the same header and footer as the index.
  - `<meta name="robots" content="noindex, follow">`.
  - Content: eyebrow "MESSAGE SENT", heading "Thanks, we've got it.", the line "We'll get back to you at the email
    address you gave us.", and a "Back to As One Strategy" button linking to `./`.
  - Fires `gtag('event', 'generate_lead', { form: 'contact' })`.

## Tooling

- `package.json` scripts, following solidtv.dev:
  - `start`: `npx live-server ./docs --no-css-inject & npm run watch`
  - `build`: `tailwindcss -i ./docs/input.css -o ./docs/output.css --minify`
  - `watch`: the same with `--watch`
  - `preview`: `http-server ./docs`
- `package.json` dependencies: devDependencies `tailwindcss@^3.4` and `http-server@^14`. No `"type": "module"`,
  so `tailwind.config.js` can use `module.exports` without depending on Tailwind's loader.
- `docs/output.css` is generated and committed, because Pages serves `docs/` with no build step. Run `pnpm build`
  after any class change.
- `.claude/launch.json` defines `asonestrategy-site`: `npx http-server ./docs -p 8139 -c-1`.

## Deployment and cut-over

1. Build everything on `static-site` and open a PR to `main`.
2. Before merge, the user supplies the Web3Forms access key. It replaces the key placeholder, which appears only on
   the branch and is never merged.
3. Merge. The Hugo workflow is deleted in the same change, so nothing redeploys. The old site stays up until step 4.
4. With the user's OK, switch Pages to a branch build with the custom domain:
   `gh api -X PUT repos/chiefcll/asonestrategy/pages -f build_type=legacy -f 'source[branch]=main' -f 'source[path]=/docs' -f cname=asonestrategy.com`
5. Right after that, the user adds these records at their DNS host. The existing Google Workspace MX records stay
   as they are.
   - `A @` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - `AAAA @` → `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`
   - `CNAME www` → `chiefcll.github.io`

   The site is unreachable from step 4 until these records propagate, usually minutes.
6. Once GitHub has issued the certificate, turn on "Enforce HTTPS", also with the user's OK.
